# Config Review Checklist

設定種別ごとのレビューチェックリスト。
参照基準: `docs/claude-code-best-practices-2026.md`

---

## CLAUDE.md

### 長さ

- [ ] 理想: 60行以下
- [ ] 許容: 150行以下
- [ ] 最大: 300行以下 (超過は指示無視が顕著に増加)

### 内容の3要素 (WHAT / WHY / HOW)

- [ ] **WHAT**: 技術スタック、プロジェクト構造が記載されている
- [ ] **WHY**: プロジェクトの目的、アーキテクチャ決定の理由がある
- [ ] **HOW**: ビルド/テスト/検証コマンドがある (実行コマンドがないリポジトリは除外)

### 含めるべきもの / 除外すべきもの

- [ ] Claude が推測できない情報のみ含まれている
- [ ] コードを読めば分かることが書かれていない
- [ ] Claude が既知の標準的な言語規約が書かれていない
- [ ] 自明な実践 (「きれいなコードを書け」等) が含まれていない
- [ ] 頻繁に変わる情報が含まれていない

### 構造

- [ ] 最重要情報がファイル先頭にある (Lost in the Middle 対策)
- [ ] コードスタイルは Linter/Formatter に委譲し、CLAUDE.md に書いていない
- [ ] 詳細情報は `@path` で別ファイルに分離している
- [ ] rules/skills との重複記載がない

### 強調

- [ ] `IMPORTANT` / `YOU MUST` は本当に重要なルールにのみ使用
- [ ] 強調の乱用がない

## Rules (.claude/rules/*.md)

### 構造

- [ ] 1ファイル1トピックに絞られている
- [ ] ファイル名が説明的 (`doc2.md` ではなく `form_validation_rules.md`)
- [ ] 関連ルールがサブディレクトリで整理されている

### paths フロントマター

- [ ] 特定ファイルにのみ適用するルールに `paths` が設定されている
- [ ] 汎用ルールに不要な `paths` 制限がない
- [ ] glob パターンが正確 (`**/*.ts` vs `src/**/*.ts`)

### 内容

- [ ] CLAUDE.md との重複がない
- [ ] 他の rules ファイルとの重複がない
- [ ] 条件付きルール (`paths` 付き) は本当に限定が必要な場合のみ

---

## Skills (skills/*/SKILL.md)

### フロントマター

- [ ] `name` が kebab-case (小文字・数字・ハイフンのみ、最大64文字)
- [ ] `description` が具体的で「何をするか + いつ使うか」を含む
- [ ] `description` が三人称で書かれている (システムプロンプトに注入されるため)
- [ ] 曖昧な名前を避けている (`helper`, `utils`, `tools` でない)

### 長さとProgressive Disclosure

- [ ] SKILL.md は 500行以下
- [ ] 詳細は参照ファイルに分離している
- [ ] 参照は SKILL.md から1階層のみ (深いネストがない)

### 呼び出し制御

- [ ] 副作用のあるワークフローに `disable-model-invocation: true` が設定されている
- [ ] バックグラウンド知識スキルに `user-invocable: false` が適切に設定されている
- [ ] 使用頻度の低い自動スキルがコマンド (手動呼出) に変換されている

### ワークフロー

- [ ] チェックリスト形式のステップに分解されている
- [ ] 「実行 -> 検証 -> 修正 -> 再検証」のフィードバックループがある
- [ ] テンプレートや例示で期待する出力が明示されている

### コンテキストコスト

- [ ] description が簡潔でトークンを浪費していない
- [ ] 自動呼出スキルの総文字数がコンテキストウィンドウの2%以内

---

## Agents (.claude/agents/*.md)

### ロール設計

- [ ] 汎用ロールでなく特化ロール (「バックエンドエンジニア」ではなく「認証フローレビュアー」)
- [ ] 1タスク1主担当が基本
- [ ] 過剰な分割がない

### 出力要件

- [ ] 出力に判断根拠が明示される指示がある
- [ ] 出力に次アクションが明示される指示がある

### ツール制限

- [ ] 必要なツールのみ許可されている
- [ ] 不要な書き込み系ツールが除外されている (読み取り専用エージェントの場合)
