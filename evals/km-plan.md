# km-plan 評価シナリオ集

挙動を変えたときに何を測り直すかの対応表と、その題材。実行時には読まない。

## 再走トリガ

| 触った箇所 | 再走する題材 |
| --- | --- |
| description | trigger-pairs |
| 確認段階でユーザーに聞く条件 | question-gate |
| 冒頭の情報量と拘束の線引き / goal-contract.md の入れるもの・点検 | decision-handoff / detail-deferral |
| レビューの人数基準・必ず 1 名通す変更 | reviewer-routing |
| blocker の条件・`READY` / `BLOCKED`・再確認 | blocker-convergence |

## 題材と合否線

- **trigger-pairs** — description 一覧のみから skill を選ばせる。should:「この機能の実装計画を issue にして」「この構造変更の背景と判断理由を残した計画を作って」/ should-not:「この bug をさくっと直して」（skill を挟まず直接実装へ）「実装が終わったので PR にして」（km-github-workflow へ）「この diff をレビューして」（km-review へ）。隣接 skill との境界と「計画を作り込む価値が無い小さな依頼」の両方を切り分けられているかを見る
- **question-gate** — 可逆な実装分岐（内部データ構造の選択など）と、ユーザーが持つ重要なトレードオフ（対外互換を切るか維持するか）を同時に含む依頼。可逆な分岐を自分で決め、トレードオフだけを選択肢 + 推奨付きで聞くのが合格。可逆な分岐まで質問へ寄せる走、トレードオフを無断で決める走はどちらも不合格
- **decision-handoff** — 複数ファイル・コンポーネントにまたがり、現実的な設計案が 2 つある変更（例: 既存 writer の再利用と新規 exporter 層の追加が並び立つ CLI サブコマンド追加）で「計画を issue にして」。読み取り専用環境で実行し `gh` 相当はテキスト報告させる。背景・現在地・各コンポーネントの責務・採用理由・代替案の不採用理由・トレードオフ・実装者の自由度が本文に残り、会話を読まない別 AI が調査をやり直さず着手できるかを見る。ゴールと作業一覧だけの本文は不合格
- **detail-deferral** — 内部ライブラリの細かな挙動・個別の異常系・テスト境界が実装中にしか確定しない変更。計画時に全列挙・過剰調査せず、実装時確認事項に、保留する理由、実装時に確認する場所、判断根拠が揃うのが合格。異常系を計画本文で網羅した実行、blocker 級の未決を実装時確認事項へ落とした実行は不合格
- **reviewer-routing** — 3 種を並べて人数の決め方だけを見る。(a) 既存パターンの直接適用で計画の土台に関わる不確実性が無い → 0 名を選び理由を残す。(b) 公開スキーマ / 移行 / 認可境界のいずれかを変える → 必ず 1 名通す判定が働く。(c) 公開契約と信頼境界が独立に重要 → 観点を分けて 2 名、同一ラウンドに三人目を足さない。**計画の長さ・ドキュメントだけの変更・規模で人数が決まった走は不合格**
- **blocker-convergence** — 局所仕様は満たすがユーザーの主目的を満たさない計画（誤ゴール）と、可逆な改善提案を混ぜる。誤ゴールを blocker として止め最小の解消策がゴール・スコープの修正を指すこと、可逆な提案を blocker にしないこと、修正後の再確認が blocker の解消と修正由来の新 blocker だけを見ること、実装時確認事項が残っていても `READY` にできることを見る

## 落とし穴

- 「issue にして」は計画を伴わない issue 起票まで引き寄せる。km-github-workflow は後続 issue の起票を PR 作成・提出の契約に含むため、この一語でトリガ語と責務範囲が交差する
- 本文の情報量は文字数で採点しない。見るのは「再調査を防げているか」と「実装経路を不要に固定していないか」の 2 軸で、長い本文が細切れの作業手順と教科書的説明で埋まっている走は decision-handoff でも不合格
- 設計案の形式要件（`<!-- km:plan:managed -->` / 「実装時確認事項」節名 / `--body-file` 全文ミラー）は成果物を見れば決まる決定的チェック。題材の評価軸に混ぜると形式要件の評価が大きくなり、測りたい設計判断を判別できなくなるため、契約チェックとして別に確かめる
