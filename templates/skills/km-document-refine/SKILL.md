# 文書の整理

読者が必要な情報を見つけ、その関係を理解し、判断・行動できる文書にする。短さを目的にせず、必要な説明を残して構成を整える。

## 対象

既存文書の情報の過不足、重複、まとまり、配置を見直す。必要な文の書き直しや、与えられた情報による説明の補足まで行う。独立した重要情報を省く要約や、新しい事実・方針の決定とは分ける。

日本語表現だけの推敲は`km-japanese-refine`で扱う。両方を求められた場合は情報と構成を整理してから表現を磨く。「読みやすく」「簡潔に」という語だけで両方を起動せず、原文の問題と依頼範囲で選ぶ。

## 構成を決める観点

以下は編集の判断軸であり、成果物に同じ見出しやすべての項目を設ける指定ではない。

### 1. 読者の問いと情報量

誰が、何を理解・判断・実行するために読むのかを捉える。読者の知識、読む場面、文書が単独でも使われるかによって、必要な説明量を決める。取捨選択を左右する重要な不明点だけを確認し、確定できる部分は進める。

要点だけでなく、それを理解するための背景・定義・根拠、行動に必要な条件、適用を示す例を残す。同じ読者・場面で同じ役割を繰り返す説明はまとめるが、別々に読まれる文書、概要と詳細、配慮を伝える前置きには異なる役割があり得る。

説明の飛躍は原文・会話・確認済み資料から補う。必要な具体例を添える場合も、既存の意味を示す架空例とし、未確認の事実や新しい条件を作らない。

### 2. 情報同士の関係

文が近くにあることではなく、意味上の関係でまとめる。

| 関係 | まとめ方・置き方 |
| --- | --- |
| 並列・比較 | 同じ問いに答える項目を、共通の軸で比べられるように並べる |
| 全体と部分 | 全体を示す見出しの下に構成要素を置き、説明とその具体例を結び付ける |
| 主張と根拠・留保 | 主張を支える根拠と、その主張が成り立つ条件・限界を近くへ置く。事実・解釈・提案は区別する |
| 条件・例外 | 対象の行動や規則と一緒に読める位置へ置く。「すべて」「いずれか」と例外の範囲を保つ |
| 順序・依存 | 前提となる情報や行動を先に置く。選択肢と実行順を区別し、分岐後の共通処理も残す |

並べ替えによって未確認の因果や優先順位を作らない。矛盾した内容を、もっともらしい規則へ統合して隠さない。

### 3. まとまりと階層

同じ問いに答える情報を一つのまとまりに集め、異なる問いは分ける。親見出しは子の内容を包む範囲を示す。比較・分類する兄弟項目は軸と粒度をそろえ、全体とその一部分を並列にしない。

文書全体には、背景・結論・手順など役割の異なる節を置いてよい。分類軸をそろえるために文書全体を同じ種類の節にしたり、説明量を均等にしたりしない。

見出しは「何が分かるか」を示す。重要な条件は対象の説明と結び付け、独立して読む節には必要な前提を残す。短い案内なら段落や箇条書きで十分であり、細かな情報ごとに見出しを増やさない。

### 4. 読む目的に合う順序

| 読者の目的 | 順序の決め方 |
| --- | --- |
| 手続きを実行する | 対象・実行前の条件を示し、行動の依存順に進める。例外は該当する段階へ置く |
| 候補を比較して判断する | 比較軸をそろえて違いを示す。結論・推奨が既にあれば要点と根拠を結び付け、未決なら勝手に採用案を作らない |
| 概念・仕組みを理解する | 読者に必要な全体像・定義から、構成要素・関係・具体例へつなぐ |
| 経緯・変化を把握する | 出来事の順序と各時点の判断・状態を区別する。移行案内では旧条件が今の行動に与える影響も残す |

用途に合わせて組み合わせ、すべてを結論先行や時系列へそろえない。現行手順に不要な作業ログは除けるが、議事録や移行案内で必要な経緯まで削らない。

### 5. 関係に合う見せ方

理由や留保をつないで理解する説明には段落、独立した項目・選択肢の一覧には箇条書き、順序が意味を持つ行動には番号付き手順が適する。複数の対象を同じ軸で見比べるには表が適する。情報量と読み方に合わせて選び、形式を一律に固定しない。

図は関係の理解を助ける場合に使う。比較軸のない短い列挙を表にしたり、文章で明確な内容を装飾のために図へ変えたりしない。名詞の羅列へ圧縮せず、誰が・何を・どの条件で行うかを伝える。

## 適用例：見出しではなく、情報のまとまりを変える

備品の貸出案内を整理する架空例。見出しと順序は自由に変更できる。

**原文**
> 【Web申し込み】利用日の前日までに申し込んでください。
>
> 【利用できる人】貸出は登録会員が対象です。
>
> 【受取】予約した備品は受付窓口で受け取ってください。
>
> 【窓口申し込み】利用日の前日までに申し込んでください。
>
> 【返却】受け取った日の翌営業日17時までに、受付窓口へ返してください。
>
> 【申し込み方法】Webか受付窓口のどちらかで申し込めます。

**整理例**
> 【利用できる人】
> 登録会員が利用できます。
>
> 【申し込み】
> Webか受付窓口のどちらかで、利用日の前日までに申し込んでください。
>
> 【受取と返却】
> 予約した備品は受付窓口で受け取ってください。受け取った日の翌営業日17時までに、同じ窓口へ返してください。

**判断**：Webと窓口を「申し込み方法」の選択肢としてまとめ、両方に掛かる期限を一度だけ示した。利用条件、申し込み、受取、返却を役割と行動の順序で分けている。見出しの言い換えだけではなく、並列な選択肢を親となるまとまりへ置き、分散していた共通条件と後続処理を結び付けた。対象・方法・二つの期限は変えず、Webと窓口の両方で申し込むという手順も作っていない。

節数や見出し名を模倣せず、情報をまとめる理由を他の文書にも適用する。

## 意味と仕上がり

事実、主体、数量・単位、否定、条件・例外の組合せと掛かり先、順序、因果・目的、確度、義務・推奨・許可等を保つ。保存すべき引用、識別子、参照先、外部指定の形式は維持し、引用枠で示された編集対象や自由な見出しとは区別する。例示を網羅的な規則へ変えない。

原文との意味の対応と、整理後だけで必要な情報をたどれるかの両方を確かめる。不明点・矛盾は分けて示し、十分に機能している説明は残す。

書き直しでは完成した本文を先に返し、重要な編集判断と未解決点だけを補足する。診断・提案では箇所、問題、修正案と理由を示す。実ファイルの変更・公開は依頼範囲に従う。
