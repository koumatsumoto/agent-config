# 保守性 (Maintainability)

ISO/IEC 25010:2023。「製品の修正の効率性と効果」を見る。可読性だけでなく観測可能性・変更局所性・テスト容易性まで含めて「後から安全に変えられるか」を確認する。

## モジュール性 (Modularity)

- [ ] モジュール境界が責務単位で明確か / 循環依存・レイヤ違反がないか
- [ ] 上位モジュールが下位実装詳細に直接依存していないか (依存方向: 具象 → 抽象)
- [ ] パッケージ / モジュール間の API がインターフェースで定義されているか
- [ ] 1 つのモジュールが複数の関心事を抱え込んでいないか

## 再利用性 (Reusability)

- [ ] 同一ロジックのコピペ / 過大関数 / 複数関心の混在がないか
- [ ] 標準ライブラリ / 既存ヘルパーで代替可能な自前実装を増やしていないか
- [ ] 依存ライブラリの EOL / 機能改善追随を意識しているか (CVE は 6-セキュリティ / 耐性側)
- [ ] 再利用される関数 / クラスがドキュメント化されているか
- [ ] API リファレンス自動生成が成立しているか

## 解析性 (Analysability)

- [ ] 命名・構造から意図が読み取れるか (深いネスト / マジックナンバー / 暗黙依存がない)
- [ ] 構造化ログ / trace ID 伝播 / メトリクスで故障箇所を絞れるか
- [ ] 重要操作にダッシュボード / アラートの起点があるか
- [ ] エラーの原因 → 結果のチェーンがログから追跡可能か
- [ ] dead code / 古いコメント / TODO 期限切れが蓄積していないか

## 修正性 (Modifiability)

変更局所性観点 (他プロセスへの共存影響は 3-互換性 / 共存性側)。

- [ ] 変更の局所性が高く、1 箇所の変更で完結するか
- [ ] 設定とロジックが分離され、依存注入 / feature toggle で切り替えられるか
- [ ] 変更時の影響範囲が静的解析 / 型 / IDE で追えるか
- [ ] 設定値の変更で振る舞いを変えられる範囲が明示されているか
- [ ] 隠れた結合 (グローバル状態 / シングルトン / モンキーパッチ) を本コード変更内で増やしていないか
- [ ] ADR (Architecture Decision Record) で意図が記録されているか

## 試験性 (Testability)

- [ ] diff の振る舞いを実際に通すテストがあるか (形式的でない)
- [ ] 実装詳細でなく契約 (振る舞い) をアサートしているか
- [ ] 実行順序・時刻・共有状態・外部実通信に依存しないか
- [ ] 公開 API / メッセージ / 設定形式に contract test / schema fixture / golden file があるか
- [ ] テストピラミッド (unit / integration / e2e) のバランスが取れているか
- [ ] フレーキーテスト (タイマー依存 / 順序依存 / 外部 IO 依存) が排除されているか

## 参照

- ISO/IEC 25010:2023
- OpenTelemetry (tracing / metrics / logs)
- Google SRE Workbook (observability)
- Martin Fowler refactoring patterns
- Renovate / Dependabot (依存陳腐化管理)
