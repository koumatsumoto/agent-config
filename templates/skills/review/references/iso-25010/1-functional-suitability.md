# 機能適合性 (Functional Suitability)

明示および暗黙のニーズに合致する機能を提供できているか。

## 機能完全性 (Functional Completeness)

- [ ] 仕様で定義された操作経路 (API / UI / CLI) がすべて利用可能か
- [ ] 列挙値・状態遷移・権限ロール・入力種別に対する分岐が網羅されているか
- [ ] 監査・再試行・キャンセル・ロールバック等の運用機能が落ちていないか
- [ ] 利用者契約上必要なフィールド・ステータス・理由コード・メタデータが返るか
- [ ] スコープ境界が守られ、仕様外の副作用が増えていないか
- [ ] エラー応答に分類 (一時的 / 恒久的) と対処方法が含まれるか

## 機能正確性 (Functional Correctness)

- [ ] 空値・null・ゼロ・最大値・部分失敗で期待通り動くか
- [ ] 境界値・等価分割の代表ケースが正しく扱われるか
- [ ] off-by-one (`<` vs `<=`、0-indexed vs 1-indexed) が混入していないか
- [ ] 数値の桁あふれ・精度損失 (浮動小数点・小数) を回避しているか
- [ ] 日時・タイムゾーン・夏時間・leap year の境界が正しいか
- [ ] 文字列の Unicode・正規化・絵文字・RTL・マルチバイトを扱えるか
- [ ] リトライ可能エラーと致命的エラーが区別されているか
- [ ] HTTP ステータス・戻り値・例外型の意味が利用者契約と一致するか
- [ ] 並行実行・競合条件下でも結果が確定するか
- [ ] バッチ処理で部分失敗時の副作用と再試行方針が定義されているか
- [ ] 冪等性が必要な操作で冪等キー (TTL / 衝突応答 / スコープ per-user か global かが明示) または状態確認が成立しているか
- [ ] 金額が ISO 4217 通貨コード + 最小単位 (整数 cents / Decimal) で扱われ、float 演算を避けているか
- [ ] 1 ユースケース = 1 トランザクション境界が成立し、トランザクション越えの副作用順序が明示されているか
- [ ] 業務不変条件 (在庫 ≥ 0、二重課金不可、合計 = 明細和、等) がコード or テストで保証されているか

## 機能適切性 (Functional Appropriateness)

- [ ] 目的達成に対し過不足のない手数か (不要な手順・呼び出しを増やしていない)
- [ ] 類似機能間でパラメータ名・戻り値・挙動が一貫しているか
- [ ] 既定値が安全性・正確性を損なっていないか
- [ ] 機能の単位が利用者の作業単位と合致しているか (粒度過大 / 過小がない)
