# prompt 資産レビューのレンズ写像

エージェント指示資産(skill / rule / `CLAUDE.md`・`AGENTS.md` / エージェントに読み込まれて挙動を規定する prompt 定義)は「読まれて実行される」挙動定義であり、その欠陥は実行時の事故を起こす。コードレビューの汎用レンズを prompt 資産の意味へ写像して当てる。**対象が挙動資産に分類された実行でのみ**読み込む(通常の code diff には当てず、全実行への固定コスト化を避ける)。

汎用レンズ → prompt 資産での意味:

- **不変条件(invariant)** = gate・収束・安全確認の伝播。本経路が通す gate(秘密チェック・承認・収束判定・silent-drop 防止など)を、新設・分岐した副経路が機械的に継承しているか。継承漏れは prompt 資産で最頻の欠陥クラス — 新しい手順・分岐が既存の安全確認を素通りする(コードでの「新エンドポイントが既存の認可 middleware を継承しない」と同型)
- **攻撃面(attack surface)** = 公開・書き込み経路。この資産が引き起こす外部公開・永続化(issue への全文ミラー、ファイル書き込み、外部送信、秘密情報の扱い)を egress として棚卸しし、意図しない公開・巻き込みが無いか
- **最悪入力(worst input)** = 最も安価な準拠挙動をとる実装者。指示を字面どおり最小コストで満たす literal な実装者を想定し、その読み方で安全確認・品質が抜け落ちないか(「善意で丁寧な読者」を前提にしない)
- **波及(ripple)** = 下流 skill との契約。この変更が他 skill との受け渡し契約(入力形式・marker・前提)を暗黙に変えていないか

役割ごとの主担当: 不変条件の継承 = Phase 2 / adversary、公開・書き込み経路 = security、下流契約の波及 = architect。担当外でも見えた懸念は出す(重複の集約は Phase 4 dedup)。
