# Body Writing Principles

issue / PR 本文の構成は固定テンプレートにしない。代わりに次の原則だけを守る。

- 読み手が次の工程へ進めるだけの情報を含める
- 設計判断、制約、スコープ外などの難所を明文化する
- 受け入れ条件は検証可能な表現にする
- 軽微な変更では簡潔に、設計判断が多い変更では詳細に書く
- 同じ内容を重複して長く書かない
- issue を計画の SSOT にする場合、正本の計画は issue body に置く
- その後の計画レビュー結果、修正提案、修正完了報告は issue comment に残す
- issue body は正本の修正に必要な最小限の更新だけに使い、レビュー履歴の上書きには使わない
