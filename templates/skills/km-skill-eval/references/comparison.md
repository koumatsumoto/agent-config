# 比較評価

変更前後や複数案の相対差が問いで、単独実行では答えられない場合だけ使う。

## 比較を成立させる条件

- 版ごとに独立したコンテキストで生成し、相手版の存在や比較目的を伝えない。
- タスク文・モデル・権限と実行可否・repo状態・日付などをそろえ、差し替えるのは対象一式のパスだけにする。
- 同じ問い・シナリオ・評価軸で、コマンド・本文・判断・最終報告などの成果物も同じ粒度でそろえる。

開始前に変更が狙う観点を名指しし、その差を主判定とする。総合的な印象は補助にとどめる。
指定がなければ、目的達成、スコープ判断（同対応 / 後続 / 対象外）、次工程へ進める成果物の質、手戻り・事故リスク（無関係な変更・逸脱・停滞）を使う。

## 必要な場合だけ追加するもの

- **版を伏せる**：版の知識が主観評価を歪める場合だけ。中立ラベルへ複製し、割り当てを固定せず、版を推測させる語が残っていないか検査する。決定的な合否・明白な差には追加しない。
- **独立評価**：版を伏せる必要があるほど主観的で、自分だけでは優劣を根拠づけられない場合だけ。生成と同じモデルを使い、提示順に意味がないと伝え、評価軸別の優劣と成果物の具体的な引用を返させる。メイン担当も観測事実と評価軸を照合する。
- **追加実行**：判定が割れる、または差とノイズを区別できない場合だけ。条件・シナリオを固定し、今回確かめることを1行示してから実行する。
- **コスト計測**：トークンや所要時間が意思決定に必要な場合だけ。

## 結論

具体的な成果物・挙動に差を帰着できる場合だけ優位を主張し、できなければ「条件内では判断に足る差を観測できなかった」とする。狙った観点に差がなく、総合評価だけが上なら、狙った効果の証拠にはしない。
走行ごとの事実誤認・シナリオ解釈の揺らぎと、資産の記述による差を分ける。分離実行や条件統一ができなければ、その比較を根拠にせず、評価案までを返して`判断保留`にする。
