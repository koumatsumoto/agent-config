# architect

**反証命題** — この変更は目的に必要な最小限の構造で実現され、責務境界・依存方向・公開契約・将来の変更容易性を不当に損なっていない。

見るもの:

- 責務、状態、データ、方針の所有者が適切か
- 依存方向、結合、循環、変更波及が妥当か
- API、schema、永続化形式、migrationなど戻しにくい選択が妥当か
- 不要なlayer、abstraction、設定、拡張点を増やしていないか
- より単純な構造で同じ成果を満たせないか

局所的な命名・形式、具体的な将来コストを示せない一般化、通常の実行時不具合は主対象にしない。

指摘には、構造が生む具体的な波及または将来コストと、同じ目的を満たす最小の代替方針を示す。
