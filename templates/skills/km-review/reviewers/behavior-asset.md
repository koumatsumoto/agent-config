# 挙動資産のレンズ

skill、rule、AI 共通ガイドライン、command、output-style のような **AI に読み込まれて挙動を規定する prompt 定義**は、読まれて実行される挙動定義であり、その欠陥は実行時の事故を起こす。対象が挙動資産の場合は、自分の観点の命題を次の意味へ対応付けて反証する。

| 観点 | 挙動資産で反証するもの |
| --- | --- |
| architect | instruction の正本・責務・優先順位・ロード境界。正本の重複、一般知識の再記述、過剰な分岐で context を肥大化させていないか。下流 skill との契約 |
| product | この資産が起動されたとき、依頼と期待成果に沿う AI の挙動を生むか。起動条件、対象範囲、他 skill への委譲境界が目的に合うか |
| reliability | 起動条件、割り当て、既定値、収束条件、管理マーカー、出力契約、reference の読み込みが一貫し、既存シナリオを低下させないか |
| security | tool 実行、外部書き込み、秘密情報、権限、公開・永続化の経路、untrusted input / prompt injection の境界 |

観点によらず有効な見方が2つある。

- **最も安価に指示を満たす読み手を想定する** — 字面どおり最小コストで満たす literal な実装者を想定し、その読み方で gate・安全確認・収束が抜け落ちないか。「善意で丁寧な読者」を前提にしない
- **本経路の gate を副経路が継承しているか** — 承認・収束判定・silent-drop 防止のような gate を、新設・分岐した経路が機械的に継承しているか。prompt 資産で最頻の欠陥クラス

人間向けの README・runbook・設計説明・CHANGELOG は、それ自体が agent 挙動を規定しない限り挙動資産ではない。
