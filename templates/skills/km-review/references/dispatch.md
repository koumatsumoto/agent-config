# 独立レビュアの起動

メイン担当の反証、修正、再検証が済んだ最終候補に対してだけ起動する。残るリスクごとに、最も適した観点を選ぶ。2名の場合は同じメッセージ内で並列起動する。

## 渡すもの

- **最終候補** — 変更ファイル一覧 + diff（`--repo` なら現状コード本文）
- **レビュー基準** — 要求意図と期待する成果、対象範囲と対象外、主要な利用者と運用者。反証可能な完了条件があれば**基準点として信頼**させ、再導出・拡張させない
- **読むファイルの絶対パス** — `reviewers/contract.md`と割り当てた`reviewers/<role>.md`の二つ。対象が挙動資産なら`reviewers/behavior-asset.md`を加える。他の観点のファイルは渡さない

## 渡さないもの

独立レビューには、メイン担当や他レビュアの所見、修正理由、修正履歴、暫定判定を渡さない。ただし再確認では、対象の問題と修正箇所を渡す。重複の集約は統合時に行う。

再確認は解消判定が目的なので例外とする（`references/recheck.md`）。

## 報告をファイルに残す

subagentはAPIエラーやセッション制限で中断しうる。完了済みの所見を破棄せず回収するために、報告をファイルへ確定させる。

- 返信の前に`<report dir>/<role>.md`（`<report dir>`はSKILL.mdで確定済み）へ報告全文と完了マーカー`<!-- km:review:report:complete -->`を書かせる。返信は件数、ファイルパス、完了阻害要因のタイトルだけとする。返信とファイルが食い違う場合はファイルを正とする
- 非 recheck の起動前に前 run の報告ファイルを空にする（前回の完了マーカー付きファイルを今回の結果と誤認しない）。recheck は前 run の `integration.md` を入力源にするので掃除しない
- 完了マーカーの無いファイルは中断された部分報告として扱い、書けた所見まで回収して安全側の判定へ接続する
- 内容は当該レビュー限りの作業物。`PASS` 確定後は不要で、機微な所見を含むならユーザー判断で削除してよい
