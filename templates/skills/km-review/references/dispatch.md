# 独立レビュアの起動

main の反証・修正・再検証が済んだ**最終候補**に対してだけ起動する。2 名のときは同一メッセージ内で並列起動する。最上位 model + 高 effort で動かす。

## 渡すもの

- **最終候補** — 変更ファイル一覧 + diff（`--repo` なら現状コード本文）
- **review anchor** — intent / expected outcome、scope / non-goals、主要な利用者・運用者。反証可能な完了条件があれば**基準点として信頼**させ、再導出・拡張させない
- **読むファイルの絶対パス** — `reviewers/contract.md` と割り当てた `reviewers/<role>.md` の 2 つ。対象が挙動資産なら `reviewers/behavior-asset.md` を加える。他の role file は渡さない

## 渡さないもの

main の所見・修正理由・修正履歴・暫定判定・他レビュアの報告。**初回レビュアは最終候補を独立に見る**ことが役割の価値で、渡せばその独立性が消える。重複の集約は統合の責務なので、レビュア側に重複回避を予測させない。

recheck は解消判定が目的なので例外（`references/recheck.md`）。

## 報告をファイルに残す

subagent は API エラー・セッション制限で中断しうる。書けたところまで回収するために報告をファイルへ確定させる。

- 返信の前に `<report dir>/<role>.md`（`<report dir>` は SKILL.md で確定済み）へ報告全文と完了マーカー `<!-- km:review:report:complete -->` を書かせる。返信は件数 + ファイルパス + blocker のタイトルのみ。返信とファイルが食い違えばファイルが正
- 非 recheck の起動前に前 run の報告ファイルを空にする（前回の完了マーカー付きファイルを今回の結果と誤認しない）。recheck は前 run の `integration.md` を入力源にするので掃除しない
- 完了マーカーの無いファイルは中断された部分報告として扱い、書けた所見まで回収して安全側の判定へ接続する
- 内容は当該レビュー限りの作業物。`PASS` 確定後は不要で、機微な所見を含むならユーザ判断で削除してよい
