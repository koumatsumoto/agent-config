# 独立レビュアの起動

該当したレビュアを**同一メッセージ内で並列起動**し、最上位 model + 高 effort で動かす。

## 各レビュアに渡す契約

- **独立性** — 他レビュアの所見も暫定判定も渡さない。他の報告ファイルを読ませない。重複の集約は統合の責務なので、レビュア側に重複回避を予測させない
- **入力** — 変更ファイル一覧 + diff（`--repo` なら現状コード本文）+ 変更構成・規模 + intent。具体的で反証可能な完了条件があれば**それを基準点として信頼**させ、完了条件を再導出・拡張させず、diff がそれを満たすかだけ軽く確認させる
- **読むもの** — `reviewers/<role>.md` を**絶対パス**で渡す（相対パスや未展開の `~` は working directory 依存で読み取りに失敗する）。挙動資産の実行では `references/generalist-review.md` の写像節も渡す
- **判定保留の規律** — 保留にする前に「あと何を読めば確定するか」を必ず一度試させる。近隣ファイルは判定に必要なだけ読んでよい（優先: 呼び出し元 / 先 → 既存テスト → 同種の既存実装）
- **出力** — 返信の前に `<report dir>/<role>.md` へ報告全文と完了マーカー `<!-- km:review:report:complete -->` を書かせる。返信は件数 + ファイルパス + CRITICAL / HIGH のタイトルのみ。返信とファイルが食い違えばファイルが正

## 報告をファイルに残す

subagent は API エラー・セッション制限で中断しうる。書けたところまで回収するために報告をファイルへ確定させる。

- `<report dir>` = repo root の `.km-review/<scope-slug>/`（引数なしは常に `uncommitted`）。同一スコープの別 run は同じパスを再利用する。セッションをまたいで発見できる固定パスであることが recheck の要件
- dispatch 前に確認する: `.km-review/` が git 追跡済みなら自動書き込みせずユーザへ確認して止まる / `git check-ignore` で無視済みなら何もしない / 未無視なら `.git/info/exclude` に `/.km-review/` を追記する（ephemeral な scratch なので committed `.gitignore` を汚さない）。これらを `git add` しない
- 非 recheck の起動前に前 run の報告ファイルを空にする（前回の完了マーカー付きファイルを今回の結果と誤認しない）。recheck は前 run の `integration.md` を入力源にするので掃除しない
- 完了マーカーの無いファイルは中断された部分報告として扱い、書けた所見まで回収して安全側の判定へ接続する
- 内容は当該レビュー限りの作業物。`PASS` 確定後は不要で、機微な所見を含むならユーザ判断で削除してよい
