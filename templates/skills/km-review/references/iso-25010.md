# ISO/IEC 25010:2023 品質特性（レビュー観点）

km-review Phase 3 の共通 lens。各レビュアは担当特性 (architect = 2/3/7/8、security = 6/9、adversary = 1/4/5) だけを当てる。**定義は書かない (既知前提)。各 expert.md の主観点が既に挙げる probe は繰り返さず、見落としやすい副特性と最も実欠陥を捕まえる角度だけを残す。** 該当しない副特性は飛ばす。所見の「観点」欄は `<番号>-<特性> / <副特性>` で書く。

## 1 機能適合性 (adversary)
- **完全性**: 全分岐・異常系を満たすか。特に "一部だけ対応" で残る穴・未実装の経路
- **正確性**: off-by-one、丸め位置、TZ / ロケール、浮動小数、符号
- **適切性**: 手段が目的に必要十分か (過剰実装・見当違い・intent 未達)

## 2 性能効率性 (architect)
- **時間効率性**: ホットパスの N+1・同期 I/O・計算量悪化・直列化
- **資源効率性**: 上限なく増える状態 (キャッシュ / バッファ / リスナ)、解放されないリソース (接続・ハンドル・ロック)
- **容量充足性**: データ量・基数・同時実行が増えて初めて破綻する前提 (全件ロード、無制限常駐)。設計上の拡張上限は 8-スケーラビリティへ

## 3 互換性 (architect)
- **相互運用性**: 公開 API・スキーマ・イベント / データ形式の破壊的変更 (後方互換欠如、consumer 連鎖、未バージョニング)
- **共存性**: 共有リソース・グローバル状態・名前空間での干渉

## 4 対話性 (adversary、UI / 対人 IF を変える diff のみ)
red-team とは別腰の generalist 観点。UI / 出力を変える diff でだけ当てる。
- **ユーザエラー防止**: 破壊的操作の確認 / 取り消し、誤操作を誘発する既定値
- **適切度認識性・アクセシビリティ**: エラー / メッセージが状況を伝え行動可能か、a11y の退行

## 5 信頼性 (adversary)
- **障害許容性**: 失敗・タイムアウト・部分障害の扱い (例外握り潰し、無限待ち、fail-open、リトライ冪等性)
- **並行・競合**: race / lost update / TOCTOU、lock 順序・デッドロック、非原子的 read-modify-write。**静的に再現を作れないことを理由に落とさない** (最も見落とされ後から最も高コストな欠陥群)
- **回復性**: 失敗後の状態一貫性 (中途半端な書き込み、orphan state、ロールバック耐性)
- **成熟性・可用性**: 既知の失敗モードの再現、デプロイ中の新旧混在挙動

## 6 セキュリティ (security)
認証認可・インジェクション・情報漏えい・暗号・供給網は `security.md` 主観点がリードする。ここは **security.md がリードしない副特性の当て漏れ防止** に絞る。
- **責任追跡性・否認防止**: 重要・不可逆操作の監査ログ、改ざん検知、後から否認できない記録
- **機密性（越境）**: テナント・ユーザ・権限の境界をまたぐデータ可視性 (LLM 文脈に限らない)

## 7 保守性 (architect)
- **試験性**: この変更の振る舞いを通すテストが **実在** し回帰を実際に捕まえるか (形式的でなく)
- **修正性・解析性**: 修正点が散る構造、誤った pattern を repo に複製・固定していないか
- **モジュール性・再利用性**: 責務分離・依存方向、循環依存、内部実装の公開リーク

## 8 柔軟性 (architect)
- **スケーラビリティ**: 負荷・データ増での設計上の上限・ボトルネック (単一ノード前提、グローバルな直列点、ロック競合)
- **適応性・置換性**: 環境 / 構成差への硬直 (ハードコード前提)、差し替え困難な密結合

## 9 安全性 (security、攻撃者でなく正当な利用者・運用者の事故)
- **フェイルセーフ・運用制約**: 危険・不可逆操作 (削除・課金・送信・本番反映) のガード / 確認 / dry-run
- **リスク識別・ハザード警告**: 誤用しやすい API・既定値、運用者が誤りに気づける警告 / ログ
- **安全な統合**: 外部・他システム連携での想定外入力・障害の波及
