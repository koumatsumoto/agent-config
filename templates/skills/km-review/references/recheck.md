# recheck（BLOCKED 後の再確認）

修正差分をコストに見合う範囲で再確認する。**著者自身による「直しました」を根拠に `PASS` にしない。**

## 起動できる条件

「直前の km-review が `BLOCKED` で、修正差分を伴う再依頼」と判断できること。判断材料は同一セッションの会話文脈、または現ターンの依頼 + 永続化された `<report dir>/integration.md`（セッション境界に依存しない）。

入力は未解決所見の一覧 + 修正差分。次のいずれかなら通常実行へ切り替え、その旨を明記する（陳腐化した所見を推測で使わない）:

- 未解決所見の一覧を入手できない
- `integration.md` の判定が `BLOCKED` でない（別 run に上書きされた疑い）
- 所見が対象差分と噛み合わない

## 実行

独立 subagent 1 名が、通常と同じ方法論（`generalist-review.md` の diff 外照合、挙動資産なら写像レンズ、報告ファイル + 完了マーカー）で **未解決所見ごとの解消 / 未解消判定**と**修正 hunk 自体の欠陥走査**を行う。main は統合と判定だけを持つ。

- `PASS` を出す前の **PASS 反証は必須**
- 修正が高リスク領域に**新たに**触れるときだけ該当レビュアを再起動する（基準は通常と同じ）
- `PASS` になったら defer 済みのドキュメントレビューを実施して確定する
- 出力形式は `verdict.md` の recheck 節

修正 hunk 外の回帰はフル再実行と同等には見ない。PASS 反証と再起動条件で緩和するトレードオフで、ユーザはいつでもフル再実行を明示指定できる。
