# ドキュメント同期

最終候補が外部から観測される面（挙動、公開契約、設定キー、コマンド、フラグ、既定値、運用手順）または文書自体を変えたとき、メイン担当が最終状態に対して1回実施する。目的は**実装と文書の不一致を防ぐこと**であって、文章の一般的な校正ではない。

1. 変更が動かした外部観測面を列挙する（API 名・フラグ・設定キー・コマンド名・既定値・出力契約・手順）
2. それらに言及する記述をリポジトリ全体から探す
   - `README`と`docs/`
   - AI共通ガイドライン（`CLAUDE.md`と`AGENTS.md`）
   - 各skillとruleの文書
   - 利用者向けのヘルプ、エラーメッセージ、コメント
3. 古い、または誤りになった記述を**修正する**（指摘で終わらせない）。修正しきれない波及だけを指摘に残す
4. 同じ情報が複数箇所にあるなら正本を一つに決めて残りは参照にする。内部リンク・参照パスの実在を確認する

文体の好み、未変更文書への一般的な改善提案、重要でない用語ゆれ、読者層に合わせた意図的な簡略化は出さない。文書由来の指摘も他と同じ重要性の判定を通し、実装と矛盾する記述、危険な手順、実在しない参照だけが完了阻害要因になりうる。

挙動資産（skill / rule / 共通 guideline）はここでは扱わない。文書ではなく code-equivalent として通常のレビュー経路で見る。
