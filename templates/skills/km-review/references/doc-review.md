# ドキュメントレビュー

コード / 設計が確定した最終状態に対して行う。扱う関心は 2 つで、どちら（または両方）を実施するかは変更構成で決まる（SKILL.md）。

違和感があれば関連ドキュメントまで辿る。明確なエラーでなくても、読者を迷わせる構成・古い記述・用語ゆれには敏感になる。

## A. コード変更のドキュメント影響（repo 全体スコープ）

変更から「外部に観測される接点」を洗い出し、それに言及するドキュメントを **repo 全体から**探して、古く / 誤りになった記述を**修正する**（指摘で終わらせない）。修正しきれない波及は指摘として残す。

探し先: `README` / `docs/` / `AGENTS.md` / `CLAUDE.md` / 各 skill・rule doc / 仕様を説明する docstring・コメント。対象語（API 名・フラグ名・設定キー・コマンド名）で横断検索する。Codex CLI では `AGENTS.md` が主で `CLAUDE.md` は fallback。

## B. 変更されたドキュメント自体の整合

**差分の周辺だけを見ない。** 変更されたドキュメント（および `docs-only` / `--repo` で対象に含まれるもの）を全体として読み、部分的な追記・修正で崩れた整合を検出して整える。

- **内部** — 全体として読み、部分修正で崩れた整合を拾う。「浮いた節」、見出しレベルの飛び（h2 直下に h4）、冒頭概要と本体の乖離、手順の番号と実ステップ数の不一致、重要な警告の埋没
- **横断** — 同じ情報の複数ドキュメントへの重複・矛盾（一方だけ更新されて放置）、内部リンク（ファイルパス・アンカー）の参照先の存在、`CLAUDE.md` / `README` / `docs/` 三重管理のずれ、用語定義の揺れ
- **一次情報** — 記述を鵜呑みにせず遡る。優先順位は repo 内の実装・設定・ヘルプ出力 → 外部一次情報。外部リンクは存在確認を基本とし、内容精査はリスクの高いもの（API 仕様・セキュリティ勧告）に限る。仕様は実装と一致するか、設定・コマンドは実際のファイルやヘルプ出力と一致するか、非推奨・廃止機能への言及や期限切れ表現が残っていないか

## 出さないもの

`reviewers/contract.md` の偽陽性フィルタに加えて、単なる文体の好み / 読者層に合わせた意図的な簡略化 / 自動生成コンテンツだけの差分 / 未変更セクションだけへの一般論。構造上の問題や読者を迷わせる構成は、明確なエラーでなくても報告・修正する。

## 重大度

`reviewers/contract.md` の 4 段階に従う。doc 観点の目安: `CRITICAL` = 危険な手順・破壊的な誤情報、`HIGH` = 明確な事実誤認・一次情報との不一致・構造破綻・コード変更に伴う必須更新の欠落、`MEDIUM` = 整合性不足・曖昧さ・更新漏れ・読者を迷わせる構成。

ここで `CRITICAL` / `HIGH` を出した場合は最終判定を `BLOCKED` に更新する。
