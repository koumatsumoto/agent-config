# 統合と判定

main の強み（ツール実行・長コンテキスト・自己反証）を「**誤った `PASS` を出さない**」ことに使う。

1. **dedup** — 全所見を `(file, ±5 行, 観点 / 根本原因)` でグルーピングする。同一欠陥の別角度記述（「境界チェック欠落」/「不変条件違反」/「OOB read」）も 1 群にまとめ、タイトルの言い回しの違い（「所有者検証なし」と「BOLA」）は照合の補助にとどめる。重複群からは最も証拠の濃い 1 件（役割固有の補足を持つもの、より高い確信度 / 重大度のもの）を残し、残した所見の末尾に**何を併合したか**と、攻撃シナリオ / 不可逆性・波及 / 再現条件のうち併合元が持っていた追加情報を注記する
2. **偽陽性を落とす** — 各 CRITICAL / HIGH が diff から具体的に裏づくか確認し、裏づかなければ降格する
3. **能動的に確かめる**（`thorough` / 高リスク昇格時、HIGH 以上の未確定分のみ）— 呼び出し元 / 先の追跡、安全な既存テストの実行、最小再現で確定 / 棄却する。確定に必要な分だけ行う
4. **`PASS` を反証する**（`PASS` 候補のときは必須）— 所見をいったん伏せ、diff が触れた surface（公開 API・契約 / 状態・データ / IO / 信頼境界 / 認証認可 / 並行・時間のうち該当する軸）を独立に列挙し、「全レビュアが揃って見逃した CRITICAL / HIGH が隠れるならどの surface か」を 1 パス問う。具体的に名指せたら手順 3 で確定 / 棄却し、確定すれば `BLOCKED` へ更新する。安価に確かめられなければ「確認推奨」ノート（重大度なし・非ブロッキング・`PASS` 維持）に「何が分かれば覆るか」を 1 行残す。**名指せないなら何も出さない** — 裏づけのない疑いで `BLOCKED` を量産しない。`BLOCKED` のときは未検査観点の 1 パス俯瞰に留める
5. **確定する** — intent があればサマリーに含め、反証可能な完了条件は基準点として信頼し、diff ↔ 完了条件の対応を軽く確認する（完了条件を再導出しない）

レビュアの「検証済み所見」は未カバー surface の優先順位付けにだけ使い、手順 4 の独立 1 パスには持ち込まない。安全ゲート系（認可・秘密情報・収束判定）の検証済み所見は、レポートに載せる前に最低 1 件スポット検証する（無検証の clear を判定根拠として表示しない）。

反証の反実仮想（surface 列挙 + 独立 1 パス）は安価なので全深度で行う。ツール実行を伴う手順 3 は `thorough` / 高リスク昇格時のみ。

## レポート

### 冒頭サマリー

**深さ**（選んだ深さ + 理由 1 行。ユーザ指定ならその旨、昇格したなら昇格理由）/ **対象スコープ** / **変更概要**（種別・行数・ファイル数。挙動資産ならその旨を明示）/ **重大度別の総件数** / **判定**（`PASS` / `BLOCKED` / `NOOP`）。

### 本体

実行した段階を順に並べる。**スキップ / defer した段階も見出しと理由を出す**（セクションごと省略しない）。各段階は件数行 + 所見、ゼロなら「指摘なし」。件数は全段階を合算し、並列レビュア分は dedup 後の件数を使う。

- 段階が結果を返さなかったら「実行失敗」として理由とともに記録し、**全体判定は安全側に倒して `BLOCKED`** とする
- 完了マーカーの無い報告ファイルは中断された部分報告として、**書けた所見まで回収して**このルールへ接続する（全損させない）
- 対象が無く終了したときは `NOOP` の 1 行だけでよい

統合レポートは `<report dir>/integration.md` にも書き出す（recheck の入力源）。

### 末尾のアクションリスト

1. **マージ前必須**（CRITICAL / HIGH）— `file:line` + `PASS` への最短経路
2. **同一 PR で修正**（MEDIUM / LOW）
3. **PR 目的の外**（follow-up issue 候補）— なぜこの PR の範囲外か
4. **共通根** — 複数の所見が 1 つの設計レベルの根本原因に束なるなら 1 文で抽出し、修正方針を根本原因の単位へ格上げして提示する

該当のないカテゴリは省いてよい。

### 判定を変えない付記

いずれも重大度なし・総件数に非算入。該当が無ければ省略する。

- **検証済み所見** — レビュアの検証済み所見を 1 セクションへ集約し、判定の根拠を可視化する（1 行 + 検証手続き）
- **確認推奨** — PASS 反証で名指せたが安価に確かめられなかった surface を、`PASS` を覆さない非ブロッキングのノートとして「何が分かれば覆るか」と 1 行で残す。確定した（裏づけ済みの）見落としはこちらではなく正規の所見として `BLOCKED` に反映する
- **受け入れ済みリスク** — ユーザ判断で直さず残すと決めた指摘だけ、**重大度 / 残す理由 / 後続対応条件**を書く。好み・様式の指摘や、変更に起因する欠陥はこの形式で残さず直す

### recheck の出力

同じサマリー形式で、各未解決所見を **解消済み / 未解消 / 新規**に区別した更新判定を出す。未解消・新規の各項目には、サマリー件数とは別に通常所見と同じ `file:line` を個別に付す（位置情報を欠いた「新規 LOW 1 件」が積もると実体を追えなくなる）。
