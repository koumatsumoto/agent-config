# Quality Patterns

Phase 2（品質特性レビュー）の詳細パターン集。ISO/IEC 25010:2023 の副特性を軸に、アンチパターンと確認観点を示す。各パターンは「diff で何を探すか」を具体的に示す。

## Tier 1: 常に確認

### セキュリティ (Security)

#### 機密性 (Confidentiality)

- ハードコードされたシークレット: API キー・トークン・パスワードの文字列リテラル、`.env`/`.pem`/`.key` の tracked 化
- ログへの機密情報混入: PII・トークン・セッション ID がログ引数やエラーメッセージに含まれていないか
- レスポンスへの内部情報漏えい: スタックトレース・DB スキーマ・内部 ID のクライアント返却
- Git 履歴へのシークレット残存: コミット間で削除しても履歴に残る

#### 真正性・責任追跡性 (Authenticity / Accountability)

- 認証の適用漏れ: エンドポイントにミドルウェア/デコレータ（TS: `@Auth()`, Python: `@login_required`）が未適用
- リソースレベル認可の粒度不足: オブジェクト ID のオーナーシップ検証なし（IDOR 脆弱性）
- セッション管理: 固定化対策・有効期限・トークンローテーションの欠如
- 監査ログ: 権限変更・データ削除・設定変更等の重要操作でログが出ていない

#### 完全性 (Integrity)

- スキーマバリデーション未適用: 外部入力が検証なしにロジックに到達（TS: Zod 未使用, Python: Pydantic 未使用）
- SQL インジェクション: パラメータ化クエリ/ORM 未使用（TS: Prisma `$queryRawUnsafe`・Drizzle `sql.raw`, Python: f-string/format SQL）
- XSS: `dangerouslySetInnerHTML`、テンプレートの未エスケープ出力（`| safe`、`{% autoescape false %}`）
- コマンド/パスインジェクション: ユーザー入力のシェルコマンド（`child_process.exec`、`subprocess.run(shell=True)`）やファイルパスへの直接結合
- デシリアライゼーション: Python `pickle.loads`・`yaml.load`（`Loader` 未指定）・`torch.load`（`weights_only=True` 未指定）、TS `JSON.parse` 後の型未検証・prototype pollution（再帰マージ）
- SSRF: ユーザー入力由来の HTTP リクエスト先、プライベート IP/ループバック未ブロック

#### 暗号化

- 非推奨アルゴリズム: MD5・SHA1（ハッシュ用途）、DES、RC4
- 非セキュア乱数: `Math.random()`・`random.random()` をセキュリティ用途に使用（→ `crypto.randomUUID()`・`secrets` モジュール）
- パスワードハッシュ: bcrypt/argon2 以外の使用、ソルトなしハッシュ
- 平文通信: TLS 未使用の外部通信、保存時暗号化の欠如

#### 耐性 (Resistance)

- レート制限なし: 認証エンドポイント（ブルートフォース）、API エンドポイント（乱用）
- リソース消費上限なし: アップロードサイズ・バッチサイズ・クエリ結果件数・リクエストボディサイズの制限欠如
- 大量データ操作の制限なし: 全件削除・全件更新が単一リクエストで可能
- サプライチェーン: ロックファイル未固定、`@scope` 未使用（npm）、既知脆弱性パッケージ、依存関係混乱攻撃（内部パッケージ名の公開レジストリ未登録）

#### ブラウザセキュリティ (Web 固有)

- CORS: ワイルドカード (`*`) 許可 + credentials、オリジン検証の欠如
- Cookie 属性: `HttpOnly`・`Secure`・`SameSite` の欠如
- CSP: `Content-Security-Policy` 未設定、`unsafe-inline`/`unsafe-eval` の使用

### 信頼性 (Reliability)

#### 無欠陥性 (Faultlessness)

- 例外の握り潰し: `except Exception: pass`、空 `catch` ブロック → fail-open の原因
- cause チェーンの欠如: Python `raise ... from` 未使用、TS エラーラッピングで original の `cause` 消失
- fail-open パターン: 認証・認可チェックがエラー時にアクセス許可にフォールバック
- 不適切な Result 型: エラー戻り値が `string | null` で型安全でない（TS: neverthrow, Python: returns ライブラリ）

#### 可用性 (Availability)

- 単一障害点: 1 つの外部サービス障害でシステム全体が停止する設計
- ヘルスチェック: Kubernetes readiness/liveness probe の欠如、DB接続チェックのみで依存サービス未確認
- グレースフルシャットダウン: SIGTERM ハンドリングなし、in-flight リクエストの完了待ちなし
- コールドスタート: サーバーレス環境で初回リクエストの遅延を考慮していない初期化処理

#### 障害許容性 (Fault Tolerance)

- タイムアウト欠如: HTTP クライアント・DB クエリ・外部 API 呼び出しにタイムアウトなし（TS: `fetch` の `signal`/`AbortController`, Python: `httpx` の `timeout`）
- リトライ: 指数バックオフなし・非冪等操作のリトライ・上限なしリトライ・ジッターなし
- サーキットブレーカー: 障害中の外部サービスへの継続的アクセス（カスケード障害の原因）
- 部分障害: バッチ処理で一部失敗時に全体ロールバック（部分成功を返すべき場面）、エラー応答に成功/失敗の内訳がない

#### 回復性 (Recoverability)

- リソース解放漏れ: Python `with`/`contextmanager` 未使用、TS `using`（5.2+）/`try-finally` 未使用
- DB コネクション・ファイルハンドル・トランザクションの解放漏れ（特にエラーパス）
- 一時ファイル・一時テーブル・ロックのクリーンアップ漏れ
- 冪等性: リトライ時に二重処理が発生する操作（冪等キーの欠如）

#### 並行性

- 同期ブロッキング: Python asyncio 内の `requests.get`・`time.sleep`・`open()`（→ `httpx`・`asyncio.sleep`・`aiofiles`）
- 無制限タスク生成: セマフォ/ワーカープールなしの並列タスク起動
- 共有ミュータブル状態: ロックなしの並行書き込み、TOCTOU 競合
- トランザクション分離: 読み取り一貫性の欠如、lost update

#### 可観測性

- 失敗パスのログ欠如: エラーハンドリング内でログを出さずに握り潰し
- 構造化ログ未使用: 文字列結合のみ、コンテキスト情報（リクエスト ID, ユーザー ID, トレース ID）なし
- 分散トレース: コンテキスト伝播の途切れ（HTTP ヘッダ/メッセージメタデータの未転送）、span の欠如
- メトリクス: 重要なビジネス操作のカウンター/ヒストグラム未計装

### 性能効率性 (Performance Efficiency)

#### 時間効率性 (Time Behaviour)

- ネストループ O(n²): 配列内線形探索（→ Map/Set に変換）、ソート済みデータの線形探索（→ 二分探索）
- 全件取得後フィルタ: DB/API 側でフィルタすべきデータをアプリケーションで絞り込み
- N+1 クエリ: ループ内の個別クエリ（→ バッチ取得/JOIN/DataLoader）
- 同期ブロッキング I/O: Python async ハンドラ内の `requests.get`・ファイル I/O、Node.js の `fs.readFileSync` をリクエストハンドラ内で使用

#### 資源効率性 (Resource Utilization)

- 上限なしインメモリキャッシュ: LRU/TTL の欠如（→ メモリリークの原因）
- ストリーム処理可能なデータの全件メモリ展開（大規模 JSON/CSV の一括読み込み）
- コネクションプーリングなしの繰り返し接続（DB, HTTP クライアント）
- Python: `all()`/`any()` にリスト内包表記（短絡評価が効かない → ジェネレータ式に）

#### 容量充足性 (Capacity)

- ページネーション欠如: 大量データを一括取得する API/クエリ
- ファイルアップロード/ダウンロードのサイズ制限なし
- キューやバッファのバックプレッシャー機構なし（プロデューサーがコンシューマーを圧倒）
- 無制限の並列リクエスト: 外部 API への同時接続数制限なし

#### フロントエンド固有 (Web)

- 不要な再レンダリング: deps 配列の誤り、オブジェクトリテラル毎回生成（React Compiler 導入済みなら手動メモ化は不要）
- バンドルサイズ: CJS 出力で tree-shaking 無効化、`import type` 未使用、動的 import 未活用
- target 設定が低すぎるポリフィル肥大化

### 保守性 (Maintainability)

#### モジュール性・再利用性 (Modularity / Reusability)

- 同一ロジックのコピペ: 共通関数/モジュールへの抽出が必要な重複
- 未使用コード・エクスポートの残存（TS: Knip, Python: vulture で検出可能）
- 過大な関数/クラス: 単一責任原則違反、複数の関心の混在

#### 解析性・修正性 (Analysability / Modifiability)

- 意図を表現しない命名: 省略しすぎた変数名、ドメイン概念と乖離した名前
- 過度に深いネスト: 早期 return で簡潔化可能な条件分岐
- マジックナンバー/マジックストリング: 定数化されていない値
- 暗黙的な依存: モジュール初期化の副作用、グローバル状態への依存

#### 試験性 (Testability)

- diff の変更を実際に検証していないテスト: 形式的に存在するだけで変更のロジックを通過しない
- 実装詳細への依存: 内部メソッド呼び出し回数の検証（→ 振る舞いを検証すべき）
- 曖昧なアサーション: `toBeTruthy`・`assert result`（→ 具体的な値を検証）
- テストの信頼性: 共有ミュータブル状態への依存、実行順序依存、時刻依存（→ 固定時刻注入）、外部サービスへの実通信
- テストの保守性: テストヘルパー/ファクトリの不使用（各テストで長大セットアップ）、テスト名が検証内容を表現していない

#### 型安全性

- TS: branded type で ID 型の混同防止（`UserId`/`OrderId`）、discriminated union で網羅的分岐、`as` による型アサーションの乱用
- Python: Pydantic strict mode で暗黙型変換禁止、`Literal` 型で値制約、`TypeGuard`/`TypeIs` で型絞り込み
- バリデーション境界: 外部入力は Zod/Pydantic で検証、内部は型を信頼。境界が曖昧な箇所で `any`/`Any` にフォールバック

## Tier 2: 変更タイプに応じて確認

### 安全性 (Safety)

#### 運用制約 (Operational Constraint)

- 入力値の上限未設定: バッチサイズ・ループ回数・再帰深度・メモリ割当て・同時接続数に制限がない
- 設定値の妥当性検証なし: 起動時バリデーション欠如（不正な設定で静かに誤動作）
- unsafe なデフォルト: `debug=true`・`cors_allow_all=true`・タイムアウトなし・リトライ無制限

#### フェイルセーフ (Fail Safe)

- fail-open: 認証・認可チェックのエラー時にアクセス許可にフォールバック
- 障害時のデータ破損: トランザクション未使用・部分書き込み・ロールバック欠如
- 安全でない状態遷移: エラー後にシステムが不整合な状態に留まる（→ 状態マシンのリセット/ロールバック）
- 縮退運転の欠如: 外部サービス障害時に全機能停止（→ 機能制限付きで継続すべき）

#### 安全な統合 (Safe Integration)

- 外部 API レスポンスの未検証: 型アサーション（`as`/`cast`）のみで実行時検証なし（→ Zod/Pydantic でパース）
- 外部システム障害の未考慮: 接続不能・タイムアウト・不正レスポンス・レート制限超過のハンドリング欠如
- ウェブフック/コールバックの署名検証なし: リプレイ攻撃への脆弱性
- バージョン不整合: 外部 API のバージョン固定なし、破壊的変更への耐性なし

### 機能適合性 (Functional Suitability)

#### API 契約の一貫性

- 同一リソースで異なるレスポンス構造: GET/LIST/CREATE で形式が不統一
- エラーレスポンス形式の不統一: エンドポイントごとに異なるエラー構造
- HTTP ステータスコードの誤用: 200 でエラー返却、バリデーション失敗に 500
- 同一フィールドの型不一致: `id` が文字列と数値で混在

#### 破壊的変更

- 必須パラメータの追加: 既存クライアント破壊（→ オプショナル化 or デフォルト値）
- レスポンス構造の変更: フィールド削除・型変更（→ バージョニング or 段階的移行）
- TS: エクスポート型の変更は MAJOR バージョン（semver-ts: "no new red squiggles" 原則）

#### 境界値・エラー網羅性

- 空配列・空文字列・null・undefined の区別が曖昧
- ゼロ値の特別扱い漏れ: 0 が `falsy` として誤判定
- リトライ可能なエラーと致命的エラーの区別がない
- 部分的な失敗の未ハンドリング: バッチ処理で一部だけ失敗した場合の振る舞いが未定義

### 柔軟性 (Flexibility)

#### 適応性 (Adaptability)

- ハードコードされた URL・パス・ポート番号: 環境変数/設定ファイルに外出しすべき値の直書き
- OS 固有パス区切り文字: `\` や `/` の直接使用（→ `path.join`/`pathlib`）
- ドキュメント化されていない環境変数への依存: デフォルト値未設定で起動時クラッシュ
- 環境変数名の衝突リスク: 汎用的すぎる名前（`PORT`、`DEBUG`）

#### スケーラビリティ (Scalability)

- ステートフルな前提: セッションのメモリ保存、ローカルキャッシュへの依存（→ Redis 等の外部ストア）
- ローカルファイルシステムへの強い依存: 一時ファイルのパス固定、ローカルストレージ前提
- 単一インスタンス前提の設計: ローカルファイルロック、インメモリキュー、プロセス内スケジューラー
- プロセス間共有状態: 分散環境で破綻する前提（グローバル変数での状態共有）

## Tier 3: 限定的に確認

### インタラクション能力 (Interaction Capability)

JSX/HTML の変更がある場合のみ確認:
- アクセシビリティ: `img` の `alt` 欠如、ボタンの `aria-label` 欠如、`div` の `onClick`（→ `button` 要素）、セマンティック要素の不使用
- ユーザーエラー防止: フォーム入力制約の欠如、破壊的操作の確認なし、バリデーションフィードバックの欠如
- エラーメッセージの質: 内部コードのみで原因や対処法が不明、技術用語のみのユーザー向けメッセージ
