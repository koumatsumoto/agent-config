# Quality Review 出力形式

## サマリー（必ず冒頭に出力）

```
## レビュー結果

**変更分類**: feat (高リスク) | 変更行数: 450行 | ファイル数: 8
**検出件数**: CRITICAL: 0 / HIGH: 1 / MEDIUM: 2 / LOW: 1
**コミット判定**: ⚠️ BLOCKED（HIGH 以上の問題あり）
```

## 品質評価サマリー（必ず出力）

問題の有無にかかわらず、9 品質特性ごとの評価を出力する。人間がこの変更の品質健全性を俯瞰するためのインサイト。

```
## 品質評価サマリー

| 特性 | 評価 | 所見 |
|------|------|------|
| 機能適合性 | PASS | 既存の操作経路は維持されている。新しい列挙値への分岐も網羅。部分失敗時の挙動も定義済み |
| 性能効率性 | PASS | N+1 の兆候なし。キャッシュに TTL 設定あり。大量データ取得にページネーション適用済み |
| 互換性 | SKIP | 公開契約の変更なし。内部 API のみの変更で外部影響なし |
| インタラクション能力 | SKIP | ユーザー/運用者接点の変更なし |
| 信頼性 | PASS | タイムアウト設定は適切。リソースはエラーパスでも解放される。リトライに指数バックオフあり |
| セキュリティ | WARN | 認証ミドルウェアの適用漏れ 1 件（新規エンドポイント）。入力バリデーションは Zod で適切に適用済み |
| 保守性 | WARN | テスト不足（MEDIUM 1 件）。新規関数のカバレッジが不十分。命名と構造は明確 |
| 柔軟性 | SKIP | 環境依存の変更なし。ハードコード値の追加もなし |
| 安全性 | PASS | 入力制約は設定済み。破壊的操作に確認ステップあり。起動時バリデーションも実装済み |
```

## 問題報告

問題ごとに以下の形式で報告する。確信度（`confirmed` = 確認済み / `suspected` = 疑い）を付与する。

```
## HIGH: 未検証の外部入力がクエリに使用されている [confirmed]

**場所**: src/api/users.ts:42
**品質特性**: セキュリティ > 完全性
**問題**: リクエストパラメータ `sort_by` が検証なしに SQL ORDER BY 句に結合されている。攻撃者が任意の SQL フラグメントを注入できる。
**修正**: 許可されたカラム名のホワイトリストで検証する。
```
