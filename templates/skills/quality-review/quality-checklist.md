# Quality Review Checklist

品質特性レビューで使用するチェックシート。Tier ごとに確認の優先度が異なる。各チェック項目を順に確認し、結果をレポートに反映する。判断に迷う場合は `reference/` 配下の該当リファレンスを参照する。

## Tier 1: 常に確認

### セキュリティ (Security)

#### 機密性
- [ ] シークレット（API キー, トークン, パスワード）がコード・ログ・レスポンスに漏えいしていないか
- [ ] 認証・認可の境界が全エンドポイント・操作経路で適用されているか

#### 否認防止
- [ ] 重要操作（決済, 承認, データ削除）に改ざん検知可能な監査証跡があるか

#### 完全性
- [ ] 外部入力にスキーマバリデーションが適用されているか（SQL/XSS/コマンドインジェクション含む）
- [ ] デシリアライゼーションや SSRF のベクトルが遮断されているか

#### 耐性
- [ ] 認証エンドポイントと高コスト API にレート制限・リソース上限があるか

### 信頼性 (Reliability)

#### 無欠陥性
- [ ] 例外の握り潰しや fail-open パターンがないか
- [ ] エラーの cause チェーンが保持されているか

#### 障害許容性
- [ ] 外部サービス呼び出しにタイムアウト・リトライ（指数バックオフ）が設定されているか
- [ ] 非冪等操作のリトライが防がれているか

#### 回復性
- [ ] リソース（DB コネクション, ファイルハンドル, トランザクション）がエラーパスでも確実に解放されるか

#### 並行性（実務補助）
- [ ] 共有ミュータブル状態への並行アクセスが安全か（ロック, TOCTOU, 無制限タスク生成）

### 性能効率性 (Performance Efficiency)

#### 時間効率性
- [ ] 不要な O(n²) や N+1 クエリ、全件取得後フィルタがないか
- [ ] 同期ブロッキング I/O がリクエストハンドラ内にないか

#### 資源効率性
- [ ] インメモリキャッシュに LRU/TTL 上限があるか、大量データを全件メモリ展開していないか

#### 容量充足性
- [ ] 大量データ取得にページネーション・バッチサイズ制限・バックプレッシャーがあるか

### 保守性 (Maintainability)

#### モジュール性・再利用性
- [ ] 同一ロジックのコピペ、未使用コード/エクスポート、過大な関数がないか

#### 解析性・修正性
- [ ] 意図が明確な命名、適切なネスト深度、マジックナンバーの定数化がされているか

#### 試験性
- [ ] テストは diff の変更を実際に検証し、実装詳細ではなく振る舞いをアサートしているか
- [ ] 曖昧なアサーション（`toBeTruthy`, `assert result`）がないか

#### 型安全性（実務補助）
- [ ] バリデーション境界が明確か（外部入力は Zod/Pydantic、内部は型を信頼）

## Tier 2: 変更タイプに応じて確認

### 互換性 (Compatibility)

- [ ] 公開契約（API, CLI, 設定, DB スキーマ）に破壊的変更がないか。ある場合、バージョニングや段階的移行が用意されているか
- [ ] 共有リソース（ポート, 環境変数, キャッシュキー）で他コンポーネントと衝突しないか
- [ ] データ形式やプロトコルの変更が、受信側/送信側の双方で整合しているか

### 安全性 (Safety)

- [ ] 入力値に上限・範囲制約が設定されているか。unsafe なデフォルト（`debug=true`, `cors_allow_all=true`）がないか
- [ ] 破壊的操作や高コスト操作に確認・警告・dry-run があるか
- [ ] 障害時にシステムが安全な状態にフォールバックするか（fail-closed、トランザクション保護）

### 機能適合性 (Functional Suitability)

- [ ] 変更後も必要な操作経路・出力・管理機能が維持されているか
- [ ] 境界値（空, null, ゼロ, 最大値）や部分失敗で正しく振る舞うか
- [ ] 既存能力で達成できることに過剰な手順を強いていないか

### 柔軟性 (Flexibility)

- [ ] ハードコードされた値（URL, パス, ポート）が環境依存を生んでいないか
- [ ] スケーリング阻害要因（ステートフル前提, ローカルファイル依存, 単一インスタンス前提）がないか
- [ ] 特定ベンダー/製品への不必要なロックインを強めていないか

## Tier 3: 接点変更があるときだけ確認

### インタラクション能力 (Interaction Capability)

- [ ] 利用者は何ができるか・何を入力すべきかを見て理解できるか（ラベル, ヘルプ, エラーメッセージの自己記述性）
- [ ] 破壊的操作や誤入力に対する防止策（確認, バリデーション, Undo）があるか
- [ ] アクセシビリティ（キーボード操作, スクリーンリーダー, 色覚差）に配慮されているか
