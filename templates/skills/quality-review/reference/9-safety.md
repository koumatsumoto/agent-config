# 安全性 (Safety)

ISO/IEC 25010:2023 の安全性に関するリファレンス。破壊的操作、危険な誤設定、フェイルセーフ、外部連携時のハザードを中心に、正当な利用者や運用者が事故を起こしにくいかを見る。

## 副特性ごとのアンチパターン + diff シグナル

### 運用制約 / リスク識別

- バッチサイズ、再帰深度、同時接続数、再試行回数などに上限がない
- 設定値の妥当性検証がなく、不正設定で静かに誤動作する
- 全件削除、一括送信、本番反映、課金確定などに確認や dry-run がない
- 閾値超過や危険な設定値に警告が出ない

### フェイルセーフ / ハザード警告

- fail-open、部分書き込み、ロールバック欠如、不整合状態への留まり
- feature flag、メンテナンスモード、一時停止条件の注意喚起が弱い
- 危険な操作が INFO ログで埋もれる、またはユーザー向け警告がない

### 安全な統合 (Safe Integration)

- 外部 API 応答を検証せず使う
- 接続不能、タイムアウト、不正レスポンス、レート制限超過を考慮しない
- webhook / callback の署名検証やリプレイ防止がない
- unsafe consumption of APIs により、外部境界を越えて危険な副作用を起こす

## surface 条件付き補助観点

- `CLI / developer tool`: destructive flag、確認プロンプト、dry-run、警告ログを見る
- `external integration`: timeout、不正レスポンス、署名検証、レート制限時の扱いを見る
- `cloud runtime / IaC`: unsafe default、公開設定、feature flag、運用停止手段の有無を見る
- `database / data store`: migration、削除系操作、ロールバック、トランザクション境界を見る

## false positive 注意

- 安全性はセキュリティと一部重なるが、攻撃者視点だけでなく正当利用時の事故防止で判断する
- 単なる UX の不便さを安全性問題にしない。事故や不可逆損失の可能性があるかを見る
- 運用手順が外部文書にある可能性はあるが、差分に危険操作の導線が見えるならコード側の警告不足として扱ってよい
