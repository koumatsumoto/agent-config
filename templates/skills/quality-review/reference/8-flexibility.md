# 柔軟性 (Flexibility)

ISO/IEC 25010:2023 の柔軟性特性に関する品質リファレンス。副特性ごとに、diff レビューで確認すべきパターンとアンチパターンを示す。

## 適応性 (Adaptability)

- ハードコードされた URL・パス・ポート番号: 環境変数/設定ファイルに外出しすべき値の直書き
- OS 固有パス区切り文字: `\` や `/` の直接使用（→ `path.join`/`pathlib`）
- ドキュメント化されていない環境変数への依存: デフォルト値未設定で起動時クラッシュ
- 環境変数名の衝突リスク: 汎用的すぎる名前（`PORT`、`DEBUG`）

## スケーラビリティ (Scalability)

- ステートフルな前提: セッションのメモリ保存、ローカルキャッシュへの依存（→ Redis 等の外部ストア）
- ローカルファイルシステムへの強い依存: 一時ファイルのパス固定、ローカルストレージ前提
- 単一インスタンス前提の設計: ローカルファイルロック、インメモリキュー、プロセス内スケジューラー
- プロセス間共有状態: 分散環境で破綻する前提（グローバル変数での状態共有）

## 設置性 (Installability)

- 手作業前提の導入: 手順化されていない初期設定、順序依存のマイグレーション、暗黙の前提パッケージ/権限
- 更新/ロールバック不能: one-way migration、後方互換性のない設定変更、失敗時の戻し手段なし
- 起動時バリデーション不足: 必須設定欠如や矛盾設定でも途中まで起動して不安定動作

## 置換性 (Replaceability)

- ベンダー SDK 直結: 抽象化なしに特定実装へ密結合し、差し替え面が存在しない
- 独自形式への固定: 標準形式やインターフェースを使わず、移行困難な独自データ形式に閉じる
- 依存逆転の欠如: 呼び出し側が具体実装を直接 new/import しており、テストダブルや代替実装に差し替えにくい
