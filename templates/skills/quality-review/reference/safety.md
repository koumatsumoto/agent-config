# 安全性 (Safety)

ISO/IEC 25010:2023 の安全性特性に関する品質リファレンス。副特性ごとに、diff レビューで確認すべきパターンとアンチパターンを示す。

## 運用制約 (Operational Constraint)

- 入力値の上限未設定: バッチサイズ・ループ回数・再帰深度・メモリ割当て・同時接続数に制限がない
- 設定値の妥当性検証なし: 起動時バリデーション欠如（不正な設定で静かに誤動作）
- unsafe なデフォルト: `debug=true`・`cors_allow_all=true`・タイムアウトなし・リトライ無制限

## リスク識別 (Risk Identification)

- 破壊的操作の無警告実行: 全件削除・一括送信・本番反映・課金確定に確認や dry-run がない
- 閾値超過の警告欠如: 上限値到達・リソース逼迫・危険な設定値でも警告ログや UI 表示がない
- 高リスクパスの識別: 決済・PII・認証に関わる変更パスに対する自動リスクスコアリングや必須レビュアー指定の欠如

## フェイルセーフ (Fail Safe)

- fail-open: 認証・認可チェックのエラー時にアクセス許可にフォールバック
- 障害時のデータ破損: トランザクション未使用・部分書き込み・ロールバック欠如
- 安全でない状態遷移: エラー後にシステムが不整合な状態に留まる（→ 状態マシンのリセット/ロールバック）
- 縮退運転の欠如: 外部サービス障害時に全機能停止（→ 機能制限付きで継続すべき）

## ハザード警告 (Hazard Warning)

- オペレーター向け注意喚起不足: feature flag, メンテナンスモード, 一時停止が必要な変更なのに実行条件がコードから読み取れない
- 危険な操作のログレベル不適切: 破壊的操作が INFO レベルでログされ、WARNING/ERROR で目立たない
- ユーザー向け警告の欠如: 不可逆操作やデータ損失のリスクがある操作に警告メッセージがない

## 安全な統合 (Safe Integration)

- 外部 API レスポンスの未検証: 型アサーション（`as`/`cast`）のみで実行時検証なし（→ Zod/Pydantic でパース）
- 外部システム障害の未考慮: 接続不能・タイムアウト・不正レスポンス・レート制限超過のハンドリング欠如
- ウェブフック/コールバックの署名検証なし: リプレイ攻撃への脆弱性
- バージョン不整合: 外部 API のバージョン固定なし、破壊的変更への耐性なし
