# 互換性 (Compatibility)

ISO/IEC 25010:2023 の互換性に関するリファレンス。API、CLI、設定、DB スキーマ、Webhook など、他の利用者やコンポーネントを壊す変更を拾う。

## 副特性ごとのアンチパターン + diff シグナル

### 共存性 (Co-existence)

- ポート、環境変数、キャッシュキー、キュー名、テーブル名、メトリクス名の名前空間衝突
- ワーカ数やプールサイズの過剰引き上げで他プロセスを圧迫する
- 固定パス、単一プロセス前提ロック、同居プロセスを無視したシグナル処理

### 相互運用性 (Interoperability)

- API、Webhook、メッセージ、CLI、設定ファイル、DB スキーマの必須項目追加・削除・型変更
- 列挙値、日時形式、タイムゾーン、エンコード、小数表現、nullability の変更
- ヘッダ名、署名方式、HTTP ステータス、エラーフォーマットの意味変更
- バージョニング、段階移行、deprecation、旧形式受理期間なしの切り替え

## surface 条件付き補助観点

- `HTTP API`: エラーフォーマット、Problem Details、認証ヘッダ、ステータスコード意味の変更を確認する
- `database / data store`: スキーマ変更、migrations、既存データとの互換性、ロールバック可否を見る
- `CLI / developer tool`: フラグ名、exit code、設定キー、出力フォーマットの互換性を見る
- `external integration`: webhook、callback、署名方式、バージョン固定、受信側 / 送信側の整合を見る

## false positive 注意

- 内部モジュールのリネームだけで利用者契約が変わらないなら互換性問題にしない
- バージョニング導入済みの破壊的変更は、移行策があるかで判断し、変更そのものを即 FAIL にしない
- Problem Details 未採用の API に対し、採用していないこと自体を問題視しない
