# インタラクション能力 (Interaction Capability)

ISO/IEC 25010:2023 のインタラクション能力特性に関する品質リファレンス。UI, CLI, 管理画面, エラーメッセージ, スクリプト化されたオペレーション手順など、diff に直接現れる接点の変更がある場合に参照する。

## 適切度認知性 (Appropriateness Recognizability)

- ラベル/コマンド名が用途を表さない: `run`, `exec`, `doit` のように意図が読めない
- 初期画面や help 出力から、何ができるかが把握できない

## 自己記述性 (Self-descriptiveness)

- プレースホルダ・ヘルプ不足: 必須入力や書式が UI/CLI から分からない
- エラーメッセージが不親切: 内部コードのみ、原因や次の行動が分からない
- 状態表示の不足: 処理中・成功・失敗が利用者に伝わらない

## 習得性 (Learnability)

- 操作手順が不自然に複雑: 初期化→設定→実行の順序依存、同じ操作に複数の別名フラグ
- 段階的な学習パスがない: 初心者向けのデフォルトと上級者向けのオプションが混在

## 操作性 (Operability)

- キーボード/支援技術で操作困難: `div` の `onClick`、フォーカス不能、ショートカット競合
- セマンティック要素不足: `button`, `label`, `fieldset`, `nav` などを使わず意図が伝わらない
- 効率的な操作の阻害: よく使う操作が深い階層にある、バッチ操作ができない

## ユーザーエラー防止 (User Error Protection)

- フォーム入力制約の欠如: 型・範囲・必須項目のその場検証がない
- 破壊的操作の確認なし: 削除・送信・反映に確認や差分プレビューがない

## ユーザー関与 (User Engagement)

- 継続利用を阻害する体験: 反応が鈍い、成功/失敗フィードバックが弱い、視認性が低い、文言が機械的で意図が伝わらない

## ユーザー支援 (User Assistance)

- 回復支援不足: Undo, 再試行, 補助メッセージ, FAQ/ヘルプ導線がない
- コンテキストヘルプの欠如: 複雑な設定画面やフォームで参照情報へのリンクがない

## 包摂性 (Inclusivity)

- アクセシビリティ属性不足: `img` の `alt` 欠如、`aria-*` 未設定、見出し階層不整合
- 色や音だけに依存: 色分けだけで状態を伝える、音通知のみで重要情報を伝える
- 多言語/現場運用未考慮: ローカライズ不能な固定文言、極端に長い専門用語、画面幅や端末制約を無視
