# インタラクション能力 (Interaction Capability)

ISO/IEC 25010:2023 のインタラクション能力に関するリファレンス。Web UI だけでなく、CLI や運用ツールの操作体験も対象にする。WCAG 2.2 は UI 変更時の補助レンズとして扱う。

## 副特性ごとのアンチパターン + diff シグナル

### 適切度認知性 / 自己記述性

- ラベル、コマンド名、help、プレースホルダが用途や入力形式を表さない
- エラーメッセージが内部コードだけで、原因や次の行動が分からない
- 処理中、成功、失敗の状態が利用者に伝わらない

### 習得性 / 操作性

- 初期化 → 設定 → 実行の順序依存が強く、正しい導線が見えない
- `div` の `onClick`、フォーカス不能、ショートカット競合などで操作しづらい
- よく使う操作が深い階層にあり、バッチ操作やショートカットが提供されない
- 反応が鈍い、成功 / 失敗フィードバックが弱いなど、継続利用を阻害する体験になっている

### ユーザーエラー防止 / ユーザー支援 / 包摂性

- 型・範囲・必須項目のその場検証がない
- 破壊的操作に確認、Undo、差分プレビューがない
- 回復支援やヘルプ導線がなく、失敗から戻れない
- 複雑な画面や設定で、コンテキストヘルプや参照導線がない
- `alt`、見出し階層、キーボード操作、色や音以外の伝達手段などの基本が欠ける

## surface 条件付き補助観点

- `Web / Browser`: WCAG 2.2 を踏まえて、フォーカス、エラー特定、ステータスメッセージ、誤操作防止を見る
- `CLI / developer tool`: help、exit code、確認プロンプト、dry-run、ログの分かりやすさを見る
- `external integration`: 運用者向けエラーや再試行導線、設定ミス時の警告が十分かを見る

## false positive 注意

- 見た目の好みだけで指摘しない。操作不能、誤操作、回復不能の実害があるかで判断する
- a11y 指摘は UI / CLI の接点変更があるときに限る
- 支援技術向け属性が既存コンポーネント抽象化の背後にある場合、差分上の属性不在だけで断定しない
