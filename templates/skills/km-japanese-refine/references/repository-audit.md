# Repository audit

リポジトリ全体を診断するときだけ読む。

## 監査単位

- 追跡対象ファイルの一覧を最初に固定する
- 日本語本文だけでなく、見出し、フロントマター、コメント、利用者向け文字列、例、テストfixtureも確認する
- バイナリ、識別子だけの設定、外部契約上変更できない文字列は「保護対象」として記録する
- 同じ問題が同じファイルで反復する場合は、適用範囲を明示した一件へ統合できる。別ファイルの箇所は統合しない

## 指摘の項目

- 一意なID
- ファイルと場所
- 変更前
- 変更後
- 修正理由
- 適用規則
- 種別: 文言修正 / 全編用語統一 / 構成変更候補 / 仕様変更候補 / 事実再確認

## 横断判断

- 用語表を作り、一つの一般概念を一つの語で呼ぶ
- コード識別子、製品固有名、出力フィールド値は用語統一の対象外とする
- 同じ記述が複数ファイルにある場合、各ファイルの読み込み文脈を確認する。独立して必要なら維持する
- 正本の移動、出力キーの変更、責務境界の変更は文章修正に含めず、仕様変更候補へ分ける
- 時点依存情報は一次情報で検証できない限り書き換えず、事実再確認へ分ける

## 完了条件

- 全対象ファイルに、指摘あり / 変更不要 / 保護対象のいずれかを記録する
- 指摘IDの欠番と重複がない
- 変更前後だけでなく理由と適用規則がある
- 仕様変更候補と事実再確認を、直接修正する文章から分離する
- 監査後の総件数とファイル別件数が台帳と一致する
