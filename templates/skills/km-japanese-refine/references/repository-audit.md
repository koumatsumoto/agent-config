# Repository audit

リポジトリ全体を診断するときだけ読む。

## 対象と記録

追跡対象ファイルの一覧を最初に固定する。本文・見出し・フロントマター・コメント・利用者向け文字列・例・テストfixtureを確認し、バイナリ、識別子だけの設定、外部契約上変えられない文字列は保護対象として記録する。
各ファイルに「指摘あり / 変更不要 / 保護対象」を付ける。同一ファイル内の同じ問題は適用範囲を示して統合できるが、別ファイルの箇所は統合しない。

各指摘に、一意なID、ファイルと場所、変更前、変更後、理由、適用規則、種別を記録する。
種別は「文言修正 / 全編用語統一 / 構成変更候補 / 仕様変更候補 / 事実再確認」とする。

## 横断判断

- 用語表で一概念一用語にそろえる。コード識別子・製品名・出力フィールド値は対象外。
- 重複は読み込み文脈を確認し、独立して必要なら残す。
- 正本の移動・出力キー・責務境界の変更は文章修正から分け、仕様変更候補にする。
- 時点依存の事実は一次情報で確認できなければ書き換えず、事実再確認に分ける。

最後に、全対象ファイルの状況、指摘IDの欠番・重複がないこと、総件数・ファイル別件数と台帳の一致を確認する。変更前後だけでなく理由・適用規則を残し、仕様変更候補と事実再確認を直接修正する文章から分離する。
