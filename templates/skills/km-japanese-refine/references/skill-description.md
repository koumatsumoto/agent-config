# Skill description

description はルーティング用のメタデータであり、skill 本文の要約ではない。

## 含める

1. 何を対象にするか
2. 何を達成するか
3. どの依頼や状況で使うか
4. 隣接 skill と誤選択する場合だけ、最小限の責務境界

## 含めない

- 内部手順、ファイル構成、subagent、人数、判定状態
- 実装上の仕組みや長い利点の説明
- 起動判断に使われない例外や背景
- 一般的な LLM 能力の説明

## 書き方

- YAML の一行で書く
- 主語を「私」「あなた」にせず、対象と働きを直接述べる
- 「何をするか」を先に、「いつ使うか」を続ける
- 抽象語だけで済ませず、実際の依頼で現れる語を含める
- 強い禁止や責務境界は、誤起動を防ぐときだけ加える

## 合否

description だけを読んだ別の AI が、起動すべき依頼と起動しない依頼を正しく振り分けられること。本文を読まないと起動条件が分からない description は失敗。

### 例

改善前:

> 日本語文書を高度な手順で分析し、必要に応じて reference を読み、意味台帳を作って推敲する skill。複数段落では詳細規則を利用する。

改善後:

> 日本語の説明・指示文を、意味と契約を保ったまま自然で簡潔な表現へ推敲する。「日本語を推敲して」などと明示されたときに使い、仕様や事実は変更せず、翻訳には使わない。

規則: 対象、目的、起動条件、必要な境界だけを残す。

注意: 隣接 skill との誤選択が起きない場合、禁止事項を増やして一行を膨らませない。
