# Security Checklist

コードレビュー時のセキュリティ詳細チェックリスト。SKILL.md の Phase 3 セキュリティ観点で参照する。

## 1. シークレット管理

- API キー、パスワード、トークンがハードコードされていないか
- `.env` ファイルや設定ファイルに機密情報が平文で保存されていないか
- ログやエラー出力に機密情報が含まれていないか
- Git 履歴にシークレットが残っていないか

## 2. 認証・認可

- すべてのエンドポイント/操作に認証が実装されているか
- 認可チェックが適切な粒度で行われているか（リソースレベル）
- セッション管理が安全か（有効期限、無効化、固定化対策）
- パスワードが安全にハッシュ化されているか（bcrypt, argon2）

## 3. 入力検証

- 外部入力がスキーマバリデーション（Zod, Pydantic 等）で検証されているか
- ファイルアップロードの種類・サイズが制限されているか
- URL やリダイレクト先がホワイトリストで検証されているか

## 4. インジェクション防止

- SQL: パラメータ化クエリ / ORM を使用しているか
- XSS: ユーザー入力がエスケープされているか、`dangerouslySetInnerHTML` 等を使っていないか
- コマンドインジェクション: シェルコマンドにユーザー入力を直接渡していないか
- パストラバーサル: ファイルパスにユーザー入力を結合していないか
- テンプレートインジェクション: テンプレートエンジンにユーザー入力を直接渡していないか

## 5. エラーハンドリングと Fail-Secure

- セキュリティ関連の例外が握り潰されていないか（fail-open の防止）
- エラーレスポンスに内部情報（スタックトレース、DB スキーマ等）が漏れていないか
- デフォルトが安全側に倒れているか（deny by default）

## 6. 暗号化

- 通信が TLS で暗号化されているか
- 機密データが保存時に暗号化されているか
- 非推奨のアルゴリズム（MD5, SHA1, DES）を使用していないか
- 乱数生成にセキュアな API（`crypto.getRandomValues`, `secrets`）を使用しているか

## 7. SSRF（Server-Side Request Forgery）

- サーバーサイドの HTTP リクエスト先がユーザー入力から構築されていないか
- 内部ネットワーク（`localhost`, `169.254.x.x`, プライベート IP）へのアクセスがブロックされているか

## 8. デシリアライゼーション

- 信頼できないデータの `eval()`, `pickle.loads()`, `JSON.parse()` + 型未検証がないか
- デシリアライズ後のデータが型検証されているか

## 9. 競合状態

- TOCTOU（Time-of-Check to Time-of-Use）の脆弱性がないか
- 共有リソースへの並行アクセスが適切に制御されているか
- トランザクションの分離レベルが適切か

## 10. ブラウザセキュリティ（Web アプリケーション）

- CORS が最小限のオリジンに制限されているか
- CSP（Content Security Policy）が設定されているか
- Cookie に `HttpOnly`, `Secure`, `SameSite` 属性が設定されているか
- CSRF トークンが適切に実装されているか

## 11. 依存関係

- 既知の脆弱性を持つパッケージが含まれていないか
- 依存関係のバージョンが固定されているか（ロックファイル）
- 不要な依存関係が追加されていないか

## 12. 不正利用防止

- レート制限が適切に設定されているか
- 大量データの取得や操作が制限されているか
- リソース消費（CPU, メモリ, ディスク）に上限があるか
