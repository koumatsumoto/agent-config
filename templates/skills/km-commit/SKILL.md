# Commit

変更を確認し、一つの目的として説明・検証・取り消しができる単位でコミットする。必要なファイルだけをステージし、複数の独立した変更が明確に分離できる場合はコミットを分ける。
コミットメッセージは、issue / PR を開かなくても `git log` / `git blame` から変更の意図と重要な判断をたどれるようにする。

## Message

### Title

- `type: 日本語の要約` または `type(scope): 日本語の要約`（type / scope は英語、説明は日本語）
- scope はリポジトリに実在する構造名（directory / package / skill 名）をそのまま使えるときだけ付ける。概念的な分類（コードに実在しない語）は発明しない
- 変更の効果・意図が分かる要約にする
- 経緯に基づく件名は書かない（「レビュー指摘を反映」「〜修正の修正」は禁止。何をどう変えるかを内容で書く）

### Body

- 内部タスク、逐次の作業ログ、レビュー往復など、最終差分の理解に不要な経緯は書かない
- 設計判断がある場合は、問題・採用した判断・その理由を書く。差分から自明な内容は繰り返さない
- 関連 issue があれば末尾に `Refs #N` を置く。`Closes` は PR 本文で扱う

誤字や形式などの自明な変更は、件名と必要に応じた 1〜2 行で足りる。無理に本文を膨らませない。

## Safety Rules

- `git add -A` / `git add .` は使わない
- `git commit --no-verify` は使わない
- push はこのスキルのスコープ外
