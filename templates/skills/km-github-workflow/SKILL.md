# GitHub Workflow

依頼された変更を、検証・レビュー済みのPRとして届ける。

## 実装

指定されたIssueがあれば要求と完了条件を確認する。設計判断を先に固める必要があれば`km-plan`を使う。Issueがないことだけを理由に新しいIssueを作らない。

既存の作業を保ちながら依頼範囲を実装し、完了条件に対応する検証を行う。作業場所やGitの操作方法は実行環境に合わせて選ぶ。

## レビュー

実装と検証を終えたら`km-review`を使う。

- `PASS`：提出へ進む
- `BLOCKED`：欠陥を修正するか、不足する検証・判断を解消し、関連検証後に`km-review --recheck`で確認する。依頼範囲では解決できない事項はユーザーへ報告する
- `NOOP`：提出すべき変更がなければ終了する

non-blockingの指摘をゼロにするためだけの反復はしない。

## 提出

依頼した変更だけをcommit・pushし、PRを作成または更新する。基点ブランチへの取り込みはPR経由で行う。

PR本文には変更理由、主要な判断、検証結果を書く。対応するIssueがあれば関連付け、実装時の確認・判断として残された事項の結果も引き継ぐ。

PR URLと検証・CIの結果を報告する。未実行・未完了・失敗はそのまま示す。

## マージ

ユーザーがマージまで依頼した場合だけ、必要なレビューとCIを満たしたPRをマージし、実際の結果を報告する。
