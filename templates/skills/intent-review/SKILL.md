# Intent Review

会話履歴を遡り、未コミット変更がユーザーの元の要求・意図を正確に満たしているかを検証する。

## いつ実行するか

このスキルは**会話コンテキストが存在する場合にのみ**有効である。

- **自分の開発をレビュー**: 会話履歴にユーザーの要求が存在する → 実行する
- **他者のコードをレビュー**: 会話履歴に関連する要求がない → スキップする

会話履歴に該当する要求が見つからない場合は、推測せずスキップする旨を報告する。

## Workflow

1. Phase 1: 変更把握
2. Phase 2: 要求の復元
3. Phase 3: 充足判定
4. Phase 4: 偽陽性フィルタリング
5. Phase 5: 報告

## Phase 1: 変更把握

`git diff --name-only` と `git diff --stat` で変更ファイルと規模を把握する。

## Phase 2: 要求の復元

会話履歴を遡り、今回の変更に関連するユーザーの要求を構造化して抽出する。以下の3カテゴリに分類する:

- **明示的な要求**: ユーザーが直接述べた機能要件・変更依頼
- **合意された設計判断**: 会話中に議論し、明示的に決定した設計方針やアプローチ
- **暗黙的な期待**: 文脈から合理的に推測されるもの（推測であることを必ず明示する）

要求が会話履歴から十分に把握できない場合は、その旨を報告し、推測で判断しない。

## Phase 3: 充足判定

Phase 2 で復元した要求に対して、変更内容を照合する。

確認観点:
- **実装漏れ**: 要求されたが実装されていない機能や対応
- **スコープ外変更**: 要求されていないが含まれている変更（意図的な改善か、スコープクリープか）
- **エッジケース・境界条件**: 要求の文脈から考慮すべき境界条件が漏れていないか
- **回帰的影響**: 変更が既存機能に意図しない影響を与えていないか
- **合意事項との整合**: Phase 2 で抽出した設計判断が実装に正しく反映されているか

## Phase 4: 偽陽性フィルタリング

報告前に各検出項目を再評価し、以下に該当するものは除外する:

- **明示的に除外・延期が合意された項目**: 会話中で「これは後で対応する」等と合意されたもの
- **段階的実装の一部**: 会話中で段階的に進める方針が合意されており、未実装部分が次のステップとして認識されている
- **意図的なスコープ制限**: ユーザーが明示的にスコープを限定した場合の、スコープ外の指摘

## Phase 5: 報告

問題の重大度を判定し、結果を報告する。オーケストレーターから呼び出された場合、構造化情報も出力する（code-review, quality-review の偽陽性フィルタリングに使用される）。

重大度（CRITICAL は本スキルでは定義しない。要件充足の観点では即時悪用可能な問題は発生せず、該当ケースは quality-review の管轄）:
- `HIGH`: 明示的な要求の未実装、合意事項との不整合
- `MEDIUM`: スコープ外変更の混入、エッジケースの考慮漏れ
- `LOW`: 暗黙的な期待への対応漏れ（推測ベース）

`HIGH` を検出した場合、コミットをブロックする。

出力形式は `report-format.md` を参照。
